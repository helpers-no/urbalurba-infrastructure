## Status: Backlog — code written, not yet run against a live cluster

**Goal**: Give UIS an in-cluster certificate-issuing capability (`uis deploy cert-manager`) —
cert-manager plus one self-signed `uis-ca` ClusterIssuer — so any service that needs a real
TLS certificate (not Traefik's ad-hoc per-connection default) has one to ask for.

**Last Updated**: 2026-10-20

**Priority**: High — a hard prerequisite for
[PLAN-service-epinio-001-install](./PLAN-service-epinio-001-install.md); Epinio's own Helm
chart requires cert-manager's CRDs to exist before its own install pass.

---

## Problem

UIS has no `cert-manager` and no in-cluster CA today — TLS to the outside world ends at the
network edge (Cloudflare/Tailscale), upstream of the cluster, and nothing issues real
certificates for in-cluster or service-to-service TLS. Two concrete consumers need one:

1. Epinio's own chart documents cert-manager as a required prerequisite, installed as a
   **separate** release first — Helm cannot apply a release's own `Certificate`/`Issuer`
   CustomResources against CRDs a bundled subchart in the *same* install pass would
   otherwise provide.
2. `urb-agents#1917`/bug [#570](https://github.com/helpers-no/urbalurba-infrastructure/issues/570):
   Authentik's shipped `authentik-server-tls` IngressRoute has `tls: {}` — no real
   certificate — which breaks any strict-TLS client (an OIDC connector, concretely). Fixing
   it needs something to issue a real cert from.

## What this PLAN ships

- `provision-host/uis/services/management/service-cert-manager.sh` — `uis deploy
  cert-manager` / `uis undeploy cert-manager`.
- `ansible/playbooks/025-setup-cert-manager.yml` — installs the `jetstack/cert-manager`
  Helm chart with its CRDs, then the standard cert-manager two-step self-signed-CA
  bootstrap: a throwaway self-signing `Issuer`, a CA `Certificate` signed by it, and the
  real `uis-ca` `ClusterIssuer` that signs everything else off that CA.
- `ansible/playbooks/025-remove-cert-manager.yml` — refuses to remove cert-manager if any
  `Certificate` outside the `cert-manager` namespace still references `uis-ca` (same
  "ask what's actually there, don't silently break it" shape as `uis argocd register`),
  unless `-e force=true`.
- Three manifests: `manifests/025-cert-manager-bootstrap-issuer.yaml`,
  `-ca-certificate.yaml`, `-clusterissuer.yaml`.

## Grounded in the proven PoC reference (2026-10-20 correction)

`urb-agents#1917`'s handoff named `terchris/home`'s `service-epinio-poc.yml` directly as the
playbook that proved gate 1 live on 2026-10-19 — this repo's own version was first written
from a guess rather than that file. Read it properly and corrected: the install flag is
`--set installCRDs=true`, **not** `crds.enabled=true` (this chart's older, since-deprecated
flag name — but it's what gate 1 actually ran and passed, so it's what this repo trusts).

## 🔴 What is still NOT verified — read before trusting this

- **No live cluster in this environment.** Every playbook here passed
  `ansible-playbook --syntax-check` and nothing more. The Helm install, the CRD wait, the
  two-step CA bootstrap, and the final `ClusterIssuer` Ready check have never actually run
  *in this repo's form* — the PoC's own install proved cert-manager itself installs and
  works, not this repo's specific two-step CA bootstrap on top of it.
- **The chart version (`1.16.2`) was not confirmed against a live Helm repo index** — the
  PoC reference didn't pin one either (plain `chart_ref: cert-manager`, whatever
  `helm repo update` resolved to on 2026-10-19). UIS's own convention is to pin for
  reproducibility regardless, so a version is pinned here, but it's a best-effort guess, not
  a verified one. Before running this for real: `helm repo add jetstack
  https://charts.jetstack.io && helm repo update && helm search repo jetstack/cert-manager
  --versions` — correct the pinned version in `025-setup-cert-manager.yml` if it does not
  exist.

**This is imac's job to run and report back on, same as every other new service.**
